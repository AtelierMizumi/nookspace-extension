3. **Automated Gecko Test Harness (`tests/mocks/browser.ts` & `tests/unit/browserApi.test.ts`)**:
   - Implemented `createMockGeckoBrowser()` simulating native Mozilla Firefox Promise-only WebExtension APIs.
   - Added 6 dedicated Gecko test cases covering storage, alarms, notifications, tabs, platform info, and rejection recovery.

## C. FIREFOX PRODUCTION BUNDLE ARCHITECTURE

The Firefox production bundle is compiled via `npm run build:firefox` (`wxt build -b firefox`) to `.output/firefox-mv2`.

### Architectural Decision: Manifest V2 vs V3 for Firefox
While Chromium strictly mandates Manifest V3 (with non-persistent Service Workers), Mozilla Firefox maintains first-class, long-term support for Manifest V2 with background event pages. This architectural choice provides significant advantages for NookSpace:
1. **Uninterrupted Pomodoro Alarms**: Background scripts in Firefox MV2 are not subject to Chromium's aggressive 30-second service worker suspension limit.
2. **Reliable Outbox Drain**: Inter-tab Pomodoro synchronization and Dexie `focusSessions` outbox processing execute with zero alarm dropouts.
3. **Broad Compatibility**: `strict_min_version: "115.0"` ensures compatibility across both modern Firefox releases and Firefox Extended Support Release (ESR 115+).

## D. COMPATIBILITY AUDIT & TECHNICAL REMEDIATION

### 1. WebExtension API Abstraction: Dual-Mode Promise & Callback Architecture
- **Problem**: In Chromium, `chrome.*` APIs historically use callbacks and populate `chrome.runtime.lastError`. In Gecko (Firefox), `browser.*` APIs return native Promises and may ignore callbacks or throw on invalid argument counts. Passing callbacks into methods that return Promises without awaiting the returned Promise could result in hung promises or unhandled rejections.
- **Solution**: Implemented `callBrowserApi<T>()` in `src/services/browser/index.ts`:
  ```ts
  function callBrowserApi<T>(
    fnWithCallback: (cb: (val: T) => void) => any,
    fnPromiseOnly: () => Promise<T> | any,
    defaultValue: T,
    ext: any
  ): Promise<T> {
    return new Promise((resolve) => {
      let settled = false;
      const done = (val?: T) => {
        if (!settled) {
          settled = true;
          if (ext?.runtime?.lastError) {
            // Suppress unchecked lastError in Chromium
          }
          resolve(val !== undefined ? val : defaultValue);
        }
      };

      try {
        const res = fnWithCallback((val: T) => done(val));
        if (res && typeof res.then === 'function') {
          res.then((val: T) => done(val)).catch(() => done(defaultValue));
        }
      } catch {
        try {
          const res = fnPromiseOnly();
          if (res && typeof res.then === 'function') {
            res.then((val: T) => done(val)).catch(() => done(defaultValue));
          } else {
            done(defaultValue);
          }
        } catch {
          done(defaultValue);
        }
      }
    });
  }
  ```
- **Platform Info Fix**: Gecko's `browser.runtime.getPlatformInfo()` resolves with an object `{ os: "win", arch: "x86-64" }`. Updated `browserApi.runtime.getPlatform()` to safely extract the `os` property from either objects or strings.

### 2. Elimination of Inline Scripts for Strict CSP Compliance
- **Problem**: `entrypoints/newtab/index.html` contained an inline `<script>` to prevent theme flashing on load. In Mozilla Firefox, extension pages enforce `script-src 'self'` by default, blocking inline scripts and causing CSP violation errors. AMO (addons.mozilla.org) also strongly discourages or rejects `'unsafe-inline'` directives.
- **Solution**:
  1. Created `entrypoints/newtab/anti-flash.ts` containing the standalone theme initialization routine.
  2. Imported `import './anti-flash';` as the very first line of `entrypoints/newtab/main.tsx`.
  3. Removed the `<script>...</script>` block from `entrypoints/newtab/index.html`.
  4. The root HTML element retains `class="dark"` by default, preventing white flash on dark theme.
  5. The output `newtab.html` now contains only external scripts (`<script type="module" src="/chunks/...">`), achieving 100% compliance with strict Firefox CSP.
